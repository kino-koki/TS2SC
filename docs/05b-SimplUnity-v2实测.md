# 05b · SimplUnity v2：MiniCPM5-1B × Qwen3-0.6B 融合（实测）

## ⚠️ 先更正一个我之前说错的事

我在方案阶段说过：**"MiniCPM5-1B 和 Qwen3-0.6B 的 FFN 中间维都是 3072，
可以逐位直搬"**。

**这是错的。** 拿到真实权重后实测：

| | hidden | FFN 中间维 | 层数 | KV 头 | 词表 |
|---|---:|---:|---:|---:|---:|
| Qwen3-0.6B | 1024 | **3072** | 28 | 8 | 151936 |
| MiniCPM5-1B | 1536 | **4608** | 24 | **2** | 130560 |

**三个维度全都不一样。** 之前那个"幸运对齐"不存在。

---

## 维度不一致意味着什么

两个模型 **无法在同一条残差流上合并任何一层**：

```
FFN 中间维 3072 vs 4608 → gate/up/down 形状全不同
hidden    1024 vs 1536 → 残差流宽度不同，层无法交错
词表     151936 vs 130560 → 不同 tokenizer，id 语义不通
```

**"逐层融合"这条路整体不成立。**

---

## 改用的设计：深度串联（depth-union）+ 双桥

让两个模型各自在**属于自己的维度**上完整工作，中间只插入两个待训练的线性桥：

```
token ids (MiniCPM5 词表 V=130560)
    ↓
emb  ← MiniCPM5.model.embed_tokens              [逐位]
    ↓
┌─ MiniCPM5 body: 24 层 @ D=1536 FF=4608 ─┐     [FFN 逐位]
└─────────────────────────────────────────┘
    ↓  bridge_down: Linear(1536 → 1024)          [可训练]
┌─ Qwen3 body: 28 层 @ D=1024 FF=3072 ────┐     [FFN 逐位]
└─────────────────────────────────────────┘
    ↓  bridge_up: Linear(1024 → 1536)            [可训练]
norm ← MiniCPM5.model.norm                      [逐位]
    ↓
head ← MiniCPM5.lm_head                         [逐位]
```

**关键：两个 body 的 FFN 权重都是原样的，一个字节都没动。**
只有 2 个桥 + 每层 mixer 需要训练。

## 踩坑（本轮新增）

### 13. `best` 权重没保存

只记了 `best` 数值，训练结束加载的是最后一步。
实测 layer0：最佳 0.6662 但最后一步 0.6630 → **加载的是差的那个**。

修法：单独存 `best_mixer`，resume 时优先恢复。

### 14. 续跑时 cosine 已衰减到 eta_min

实测：全新 150 步 → 0.6834；resume 到 300 步再续跑 → 卡在 0.6662 上不去。

修法：每次续跑重置 cosine 周期 `T_max = 剩余步数`。

### 15. MSE 下降但余弦也下降

```
step 270  loss 0.005481  cos 0.6645
step 275  loss 0.145469  cos 0.6305
```

MSE 和余弦不对齐 → 加 `cosine` 项：`l = mse + 1.0 * (1 - cos)`。

### 16. fp32 中转导致 OOM

1.5B 参数 fp32 = 6GB，内存 2.4GB → 进程被杀。
修法：`put()` 里立即转 bf16。

### 17. `raw.githubusercontent.com` 慢 800 倍

```
raw.githubusercontent.com   0.01 MiB/s
api.github.com blob (raw)   8.00 MiB/s
```

2.1GB 权重：前者要 58 小时，后者 296 秒。
**必须用 API blob 端点 + `Accept: application/vnd.github.raw`。**
