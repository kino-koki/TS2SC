# 01 · 架构映射

## 结构同构性（整个方案的地基）

```
Transformer Block            SimplCore Block
─────────────────            ───────────────
x                            x
├─ input_layernorm           ├─ mixer.norm        ← 直搬
├─ self_attn (QKV)           ├─ mixer (SGC)       ← 转换
├─ o_proj                    │  └ out_proj        ← 直搬
├─ + residual                ├─ + residual
├─ post_attention_layernorm  ├─ ffn.norm          ← 直搬
├─ mlp (gate/up/down)        ├─ ffn (gate/up/down)← 直搬
└─ + residual                └─ + residual
```

**除 mixer 外，其余结构完全同构。**

参数占比（D=dim，FF=ffn 中间维）：

```
Attention = 4·D²      （Q/K/V/O 四个投影）
FFN       = 3·D·FF    （gate/up/down，SwiGLU）
```

当 FF = 3D 时：Attention = 4D²，FFN = 9D² → **FFN 占 69%**。
**这是"知识主体可以完整继承"的量化依据。**

## GQA 派生规则

Qwen3-0.6B：Q 有 16 头，K/V 只有 8 头，D=1024，head_dim=128。

```
q_proj: (16×128, D) = (2048, D)   ← 超出 D
k_proj: ( 8×128, D) = (1024, D)   ← 正好 D×D ✅
v_proj: ( 8×128, D) = (1024, D)   ← 正好 D×D ✅
o_proj: (D, 16×128) = (D, 2048)   ← 需切片
```

| SimplCore | 来源 | 操作 |
|---|---|---|
| `mixer.in_proj` (D,D) | `v_proj` | **直搬** |
| `mixer.gate_proj` (D,D) | `k_proj` | **直搬** |
| `mixer.out_proj` (D,D) | `o_proj` | **切片** `[:, :D]` |

**为什么 v_proj → in_proj**：V 是"被聚合的内容"，与 SGC 卷积输入语义最接近。
**为什么 k_proj → gate_proj**：K 决定"哪些位置重要"，与门控语义最接近。

这是**工程启发式，不是数学最优**，实测残差 0.0773。

## ③ 重组通道：层数不足

若 teacher 层数 < student 层数（如 24 → 28，或 28 → 74）：

```python
alpha = 0.5 + 0.35 * sin(1.7 * i)
W_new = W_src1 * alpha + W_src2 * (1 - alpha)
```

**确定性、可复现**（无随机），不同层得到不同组合。

⚠️ **诚实说明**：凸组合**不增加知识**，只提供"待训练的高质量起点 + 容量"。
这些层必须参与蒸馏。

## 词表不一致（最容易毁模型的一步）

| 情况 | 处理 |
|---|---|
| 词表相同 | 直搬 embedding + head |
| 词表不同 | **必须换 tokenizer**，embedding 只能重建 |

⚠️ 曾经用自训 8192 词表替换 Qwen3 的 151936，导致
**311M embedding 参数随机初始化** —— 模型直接报废。

**去风格化应该靠后训练（SFT 数据），不是靠换词表。**

## FFN 中间维对齐的运气

```
Qwen3-0.6B:   intermediate_size = 3072
MiniCPM5-1B:  intermediate_size = 3072
```

**两者相同** → 融合时 B 的 24 层 FFN 可以**逐位直搬**，零维度变换。
这是 SimplUnity 里最容易出错的一步被天然省掉。

若 FF 不同：
- FF 更大 → 切片 `[:target]`
- FF 更小 → 确定性扩维（`simplunity.py: expand_last_dim`）

## 支持范围判定

`config.json` 满足以下条件即可直接迁移，**无需改代码**：

```json
{
  "architectures": ["LlamaForCausalLM"],
  "model_type": "llama"
}
```

且权重键名为 `model.layers.{i}.self_attn.{q,k,v,o}_proj.weight`
与 `model.layers.{i}.mlp.{gate,up,down}_proj.weight`。

已验证 / 预期兼容：Qwen2/2.5/3、MiniCPM5、TinyLlama、LLaMA、Mistral。
