## 0. 方案定稿

**SGC 主干完全冻结**：`ψ_m[τ]=ρ_m^τ·sin((τ+1)θ_m)`、`a/b/c` 静态 Toeplitz、FFT↔IIR 双形式、`2·M·D` 定态，一个字节都不改。

**三条旁路并联，只在 `readout` 拼接，绝不回写主干**：

| 旁路 | 补的能力 | 状态 |
|---|---|---|
| A 3 层 k=7 门控短卷积 | 局部 n-gram / 乘法交互 | `3·6·D` |
| B CfC 液态门（v1 纯门 / v2 加积分态） | 输入依赖 τ / 不规则 Δt | `D`（v2 `2D`） |
| C Hadamard 正交登记（SE1） | 内容寻址绑定，地址由内容非位置给 | `V×V` = 32 KiB |

汇合：`concat[sgc_out; f_A; f_B; f_C]` → ridge 线性探针。写入由 L1 门控制；无关段走闭式跳跃。

**纯度**：无 Q/K/V、无 `softmax(QKᵀ)`、无 SDPA、无 KV cache、无位置表、无 `max_len`；mixer 白名单仍为 `sgc / sgc-nogate / sgc-nolocal / srf`，不新增任何注意力开关。

## 3. 不足 / 不能宣称的地方（全部列出，不打折）

### ❌ 3.1 真实语料语言建模质量：**完全未测**
PPL、LRA、长文档、中文语料、1B+ 规模、端到端训练、真实分布漂移、多 needle、层级运算（仓库自承 attention 强项）——**一项都没跑**。所有结论停留在合成诊断与机制层断言。不得据此宣称 SOTA 或「通用超越」。

### ❌ 3.2 attention 对照是构造性 oracle，不是训练好的 Transformer
三臂全是零训练 `x@x.T` + shift-1 value 的 induction-head 式上界。所有「+0.058 / +0.119」都是**对这个 oracle** 的差值。真实 Transformer（带位置编码、训练过的 QKV）在这些任务上很可能更高。

### ❌ 3.3 T2 不构成超越证据（必须划掉）
T2 局部 n-gram：**所有 SGC 臂都 1.000，包括 `SGC_frozen_only`（纯主干，零外挂）** —— 说明这是 SGC 自带局部卷积的能力，**外挂零边际贡献**。attention 公平上界 0.593 明显偏弱（真实带位置的 Transformer 不会只有 0.593）。这一轴既不能算外挂的功劳，也不能算架构超越。

### ❌ 3.4 三块外挂里只有一块在 T1 起作用
`no_shortconv = 1.000`、`no_liquid = 1.000` —— A（短卷积）和 B（液态门）在绑定召回上**边际贡献为零**。「3-sidecar」这个名字有虚高成分，实际是 **1 块必需 + 2 块在特定任务上才有用**。

### ❌ 3.5 T3 v1 是明确负结果
纯 CfC 门（无积分态）= **0.332 ≈ chance**。靠新增 `integral` 状态才到 0.702，且 0.702 本身远低于 1.0。说明「把 LNN 接成外挂」并不自动带来不规则采样能力，必须显式设计状态积分。

### ❌ 3.6 T1 的 1.000 是机制存在性验证，不是「模型学会了召回」
Hadamard 读出 `C[k]S @ C[VK:]ᵀ` 是**解析 one-hot 恒等式**（`IDENTITY`，on 误差 0.0、off 0.0），ridge 探针 trivially 学会。它证明「零串扰在超长 L 下不退化」，不证明「模型从数据里学会了检索」。

### ❌ 3.7 长度外推用了 oracle 写入门
`gate=1` 的 pair token 是**生成器给出的**，无关段用 `gate=0` 精确屏蔽。真实流式输入没有这个 oracle 门，L1 门必须学出来，**这一项未验证**。

### ❌ 3.8 对写入门质量高度敏感（SE3 实测印证）
| 写入噪声 p | 0.00 | 0.05 | 0.10 | 0.20 | 0.30 | 0.50 |
|---|---|---|---|---|---|---|
| acc | 1.000 | 0.978 | 0.947 | 0.927 | 0.868 | 0.605 |

5% 误写就掉点，30% 掉到 0.868，50% 掉到 0.605。统计门控是必要条件，不是可选优化。

### ❌ 3.9 定容语义有硬拐点
| G | 4 | 8 | 16 | 24 | 32 | 40 | 48 | 64 |
|---|---|---|---|---|---|---|---|---|
| G/VK | 0.12 | 0.25 | 0.50 | 0.75 | 1.00 | 1.25 | 1.50 | 2.00 |
| acc | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | **0.825** | **0.656** | **0.497** |

超过 Hadamard 半区 VK=32 后共享码本行，SE1 正交性失效，掉到近 chance。这是**信息论上限**，不是调参问题。要扩容量只能增大 V（状态 `V²` 平方增长）——效率优势会被吃掉。

### ❌ 3.10 账本 ≠ 实测
- `46,656 B` 状态是**代数账本**（LEDGER），不是实测显存；
- attention 的 `INFEASIBLE` 是 **HBM 账本判定**，不是实跑它失效；
- 吞吐 `200,000 步 / 约 11.2 s ≈ 0.018 Mtok/s` 是**纯 numpy fp64 CPU 实测**，非常慢，不可外推到 CUDA/HIP/ROCm 后端。wall-clock 随机器负载波动（两次复跑 11.82 s / 11.25 s），已在 340 字段确定性比对中**显式排除**，不计入可复现数值。

### ❌ 3.11 等价实现，不是仓库源码执行
沙盒无 torch，无法直接 import `simplcore/core/arch/sgc.py`。`FrozenSGC` 是按仓库 README / `SGC_CORE.md` 公式写的 **numpy fp64 数学等价黑盒**。仓库自身也已把 PyTorch 实现「退役为冻结数值规格（oracle）」，生产走 CUDA/HIP。所以本验证是**等价实现验证**。
CI 复现的是 `purity.py` 的判定口径（标识符表 / 定义性 AST 扫描 / mixer 白名单 / 负向变异）与 `contract_check.py` 风格静态审计，**不是真跑仓库 pytest 套件**。

### ❌ 3.12 未测的数值与工程项
fp16/bf16 数值误差、长核 fp32 误差累积（仓库自承 `<4e-5` 只适用 `L≲512`）、复数/相位精度、HIP 16-op 契约对接、`--train-chunk` 分块 BPTT、多卡 DDP、真实 tokenizer/词表（本实验 V=22 的合成嵌入）。

### ❌ 3.13 评测口径是线性探针，不是端到端训练
ridge + 固定特征，3 seeds、300 训练 / 200 测试样本/seed，合成任务。所有 acc 是**探针可分性**，不是模型生成质量。

### ❌ 3.14 证据链自洽 ≠ 外部复现
仓库页面为 0 star / 0 fork、无同行评审；本包是我在本沙盒内自洽复现，尚未有第三方独立运行。

## 4. 结论（不喊口号，给边界）

**成立的部分**：在 SGC 主干**逐位冻结、纯度 37/37、状态恒 46,656 B** 的前提下，内容寻址旁路把合成绑定召回从 chance 拉到 1.000（超构造性 attention 公平上界 +0.058），并把可行性推到 L=16,777,233 —— 那一档 attention 按 HBM 账本已 INFEASIBLE。加上积分态的液态旁路在不规则 Δt 上超公平上界 +0.119。独立复跑 340 字段零差异。

**不成立 / 未验证的部分**：真实语料 LM 质量完全没测；所有「超越」都是对零训练 oracle；T2 与外挂无关；三块外挂只有一块在 T1 起作用；T3 v1 是负结果；T1 是解析恒等式而非学习；写入门用了 oracle；容量 G>32 崩；账本与实测要分开看；等价实现而非仓库源码；线性探针而非端到端。

一句话：**这是一个「机制层可运行断言成立、长度/成本轴真实越过 attention 结构边界」的工程验证包，不是一个「通用超越 attention 的模型」。** 仓库 README 那句「不是更好的模型，是唯一成本可行的选择」仍然适用——我这次只是把「可行的长度」从 1M 实跑推到了 16.7M，并把它钉成了可复现的数字。
